# CAAS（カーズ）— Chat–Agent Auto Session

> ⚠️ **CAAS ゲート（`code/gate/caas_gate.js`）を入れずに CAAS を使わないでください。** ゲートがないと、チャットに話しかけられる人なら誰でも、PC の上でどんな命令でも動かせてしまいます。「安全について」を先に読んでください。

**CAAS は、いつもの Claude.ai の会話に話しかけるだけで、同じ PC ですでに動いている Claude Code の席が仕事をし、その結果が人の手を借りずに同じ会話へ戻ってくる仕組みです。**

技術ノート（DOI）：[10.5281/zenodo.23005933](https://doi.org/10.5281/zenodo.23005933)・作者：Rurimpa（技術ノートでの筆名＝がけっぷちのふくしゃちょう）

## 5分で動かす：3手（Windows で確認）

要るもの＝Windows の PC・Claude Desktop・Claude Code・Node.js。

**① ゲートを入れる**（Claude Desktop で）

[`caas-gate.mcpb`](https://github.com/Rurimpa/caas/releases/latest/download/caas-gate.mcpb) をダウンロードし、Claude Desktop の「設定」→「拡張機能」→「詳細設定」→「拡張機能をインストール…」でそのファイルを選び、「インストール」を押します（ダブルクリックで Claude Desktop が開く PC もありますが、開き方を聞かれる PC もありました）。入れた直後に「拡張機能サーバーに接続できません」と赤く出ることがありますが、チャットからは使えていました（2026-10-02 に Windows で確認）。**設定（トレイの場所・話しかけてよい席）を変えたら、Claude Desktop をタスクトレイから終了して起動し直してください**（「有効」のスイッチの切り入れだけでは、チャットからの呼び出しに古い設定が残りました）。ゲートは起動のたびに、受け取った設定と実際に使う設定を `C:\Users\<あなたの名前>\caas\gate_record.jsonl` に1行書きます。ゲートは Claude Desktop の拡張機能として入ります。設定は初めの値のままで動きます（トレイ＝`C:\Users\<あなたの名前>\caas\chat_agent_tray`・話しかけてよい席＝`CAAS_agent_1`、`CAAS_agent_2`…）。

（拡張機能を使わずに手で入れる道＝`npx github:Rurimpa/caas#v1.2.2 setup`。くわしくは QUICKSTART.md）

**② 仕事をする席を用意する**（Claude Code で）

```
/plugin marketplace add Rurimpa/caas
/plugin install caas@caas
```

そのあと、仕事をさせたいフォルダで席を立てます：`claude --name CAAS_agent_1`

**③ チャットにスキルを入れて、話しかける**（Claude.ai で）

1. [`chat-skill/caas-chat.zip`](chat-skill/caas-chat.zip) を、Claude.ai の「設定」→「機能」→「スキル」からアップロードします。
2. 新しいチャットで何か1通送り、会話の名前の横の PC のマークから **Link to this computer** を選びます（会話ごとに1回。ここだけは人の操作です）。
3. 「Set up CAAS」と送ります。チャットが自分で確かめて、呼び鈴を作ります（トレイを初めの値から変えたときは、その場所も一緒に送ります）。

あとは「CAAS_agent_1 に〇〇を頼んで」と話しかけるだけです。

## なにが新しいのか

チャットから動いている Claude Code の席へ頼むこと、予約の仕組みで会話を起こすこと、それぞれは公開されている例があります。けれど、私たちが見つけた例はどれも、答えを受け取るところで人が一手を打つ必要がありました（「get」と打つ、「どう？」と聞く、など）。

CAAS は、その最後の一手も要りません。

- 人が話しかけるのは、**いつもの**会話です（専用の窓口ではありません）。
- 仕事をするのは、**すでに動いている**席です（その場で作る使い捨ての席ではありません）。
- 答えは、**人が何もしなくても**同じ会話に戻ってきます。

## しくみ

土台の考え方（Claude Code の席どうしが用件をやり取りするときの作法）は、スキル [cross-session-messaging](https://github.com/Rurimpa/cross-session-messaging) にまとめてあります。CAAS を使わなくても、それだけを2行で入れて使えます。

```
[いつもの会話] --(1) 頼み--> [ゲート] --> [動いている Claude Code の席]
      ^                                          |
      |                                 (2) 答えを紙（ファイル）に書く
      |                                 (3) 呼び鈴を鳴らす
      +------(4) 会話が起きて紙を読み、続きを話す------+
```

1. **行き：** 会話は、ゲートを通して、動いている席へメッセージを送ります。1行目には目印（`[chat_agent_tray <依頼番号> reply-to=<置き場> bell=<呼び鈴の番号>]`）を書きます。
2. **帰り（紙）：** 席は、答えを置き場（トレイ）のフォルダに `.md` の紙で置きます。1行目は `FROM <席の名前>`、最後の行は `END` です。
3. **帰り（呼び鈴）：** 紙を置いてから、席は呼び鈴（会話の中で作った1回きりの予約）を鳴らします。
4. 会話が自分で起きて、置き場の紙を読み、人への話を続けます。読み終えた紙は `done/` に移します（消しません）。

## CAAS ゲート

`code/gate/caas_gate.js` は、Claude Desktop と Claude Code のあいだに入る小さな見張りです（Node.js・AI は入っていません）。

- 会話が使える Claude Code の道具は、**4つだけ**です（`ListAgents`・`SendMessage`・`Read`・`Glob`）。
- `Read` と `Glob` で見られるのは、**置き場のフォルダの中だけ**です。秘密らしいファイル（`.env`・鍵など）は、置き場の中でも断ります。
- `SendMessage` で送れるのは、**名前を決めた席だけ**です（`CAAS_SEND_ALLOW_RE`）。
- 読めない頼みは断ります（fail-closed）。

## 安全について

- **ゲートが守らないもの：**
  1. 同じ Claude Desktop に入っている、ほかの PC の道具（ファイル操作や画面操作の拡張など）。会話からはゲートを通らずに使えます。ご自分で見直してください。
  2. 頼まれた席が何をするか。ゲートが見るのは宛先の名前だけで、席はその席自身の権限の設定で動きます。
- Claude Code の権限の設定（`permissions.deny`）は、この経路では効かないことがありました（2026-09-28 の実測）。**守りはゲートで行います。**
- 置き場には、頼みの本文を置きません（紙を置けば誰でも席に命令できてしまうため）。答え・途中経過・質問だけを置きます。

## 知っておくこと

- 公式の説明にない動きを使っています。いつ使えなくなってもおかしくありません。
- 呼び鈴が起こすのは、それを作った会話1つだけです。新しい会話には、新しい呼び鈴を作ります。
- **新しい会話は、はじめは PC につながっていません。** 会話を始めてから、会話の名前の横の PC のマークで「Link to this computer」を選びます（「新規」の空の画面では選べません）。
- **PC とつながった会話を共有すると、「公開」にしても claude.ai にサインインしている人にしか見えません。** また、共有した会話は見るだけで、相手が書き込むことはできません。お客さんなど外の人に質問してもらう用途には向きません。
- 試したのは PC 1台だけです（Windows 11・Claude Desktop・Max プラン、2026年9月）。
